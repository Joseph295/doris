# 第一部分：全局架构与设计哲学

这一部分建立读整套教程所需的全局心智模型：Doris 是一个什么定位的系统、它由哪几个进程组成、数据如何分层组织、同一份代码如何长出两种架构形态，以及怎么把这份代码编译、调试、跑起来。它是后续所有部分的地基——从第二部分起，讲执行路径、讲元数据、讲存储引擎时都默认你已经掌握了这里的组件边界、数据模型与开发环境。

这五章之间是递进的：先认识系统与进程（第 1、2 章），再理解数据怎么摆放（第 3 章），然后看清两种架构形态的分叉（第 4 章），最后把前面这套认知落到能实际操作的源码地图与开发环境上（第 5 章）。建议按顺序通读，并务必跟着第 5 章把本地 ASAN 开发环境搭好——后续每一部分的动手实验都以此为前提，不再重复环境说明。

| 章节 | 主题 | 关键收获 |
|---|---|---|
| [第 1 章](01-positioning.md) | Doris 是什么样的系统 | MPP / 列存 / 实时分析的定位与取舍 |
| [第 2 章](02-three-components.md) | 三大件解剖 | FE / BE / MetaService 的职责边界与进程结构 |
| [第 3 章](03-data-model.md) | 数据模型 | Table→Partition→Tablet→Rowset→Segment 层级与三种数据模型 |
| [第 4 章](04-two-architectures.md) | 两种架构形态 | 存算一体 vs 存算分离的双模式差异总表 |
| [第 5 章](05-source-map-and-dev-env.md) | 源码地图与开发环境 | 仓库导览、ASAN 编译、调试手段、编译调试基本功 |

读完这五章，你应当能画出组件间的调用关系、说清一条数据从表到 Segment 的分层、判断任意一段源码在哪种模式下生效，并独立编出一个集群跑通回归用例。
